# Downloading an SFTP File via a Kubernetes Pod

Use a Kubernetes pod as a temporary relay when your local machine cannot directly access the SFTP server.

## 1. Download from the SFTP server into the pod

From your local PC, run:

```sh
kubectl exec -n <namespace> -i <pod-name> -- \
 scp -P 22 810074@pelaporan.afpi.or.id:/remote/path/to/file /tmp/report.csv
```

Enter the SFTP password when prompted.

## 2. Copy the file from the pod to your local Downloads folder

Still from your local PC, run:

```sh
kubectl cp -n <namespace> <pod-name>:/tmp/report.csv ~/Downloads/report.csv
```

### For a specific container

```sh
kubectl cp -n <namespace> -c <container-name> \
 <pod-name>:/tmp/report.csv ~/Downloads/report.csv
```

## If interactive password entry is awkward

Interactive password entry through `kubectl exec -i` can be awkward. If your terminal supports it, use `-it` to open a shell in the pod instead:

```sh
kubectl exec -n <namespace> -it <pod-name> -- sh
scp -P 22 810074@pelaporan.afpi.or.id:/remote/path/to/file /tmp/report.csv
exit
```

Then run `kubectl cp` locally to download the file from the pod.

## If `scp` is unavailable in the pod

Use one of these alternatives:

- Use the pod's `sftp` client instead, if available.
- Launch a temporary debug pod in the same namespace/network with `openssh-client` installed, download the file there, then use `kubectl cp` to copy it to your local machine.

assistant: Use `sshpass`. The least-bad non-interactive form is via an environment variable rather than embedding it in the command:

```sh
kubectl exec -n <namespace> -i <pod-name> -- \
  env SSHPASS='your-sftp-password' \
  sshpass -e scp -P 22 \
  810074@pelaporan.afpi.or.id:/remote/path/to/file \
  /tmp/report.csv
```

If the pod does not have `sshpass` installed, you’ll need a pod/image that includes it.

You *can* put it directly in the command:

```sh
sshpass -p 'your-sftp-password' scp -P 22 ...
```

…but don’t. It can end up in shell history, process listings, terminal logs, and potentially audit logs. The `SSHPASS` version is still sensitive, but avoids exposing it in the process arguments.
