# Erudifi Commit Messages

Follow these conventions when creating commits for Erudifi projects.

## Prerequisites

Before committing, always check the current branch:

```bash
git branch --show-current
```

**If you're on `main` or `master`, you MUST create a feature branch first** — unless the user explicitly asked to commit to main. Do not ask the user whether to create a branch; just proceed with branch creation. The `create-branch` skill should derive and create a suitable branch name automatically.

Use the `create-branch` skill to create the branch. After `create-branch` completes, verify the current branch has changed before proceeding:

```bash
git branch --show-current
```

If still on `main` or `master`, stop — do not commit.

## Pre-commit checks

Before committing, if the repository contains a pre-commit configuration (for example `.pre-commit-config.yaml` or `.pre-commit-config.yml`), run the repo's pre-commit checks in lint-only mode against the files being committed and make sure they pass before creating the commit.

Guidance:

- Prefer running pre-commit only on the staged/changed files rather than the entire repository when possible.
- If the repo uses `pre-commit`, use a command pattern like:

```bash
pre-commit run --files <changed files>
```

- If the repository has a documented lint-only wrapper or make/npm task that is clearly the pre-commit equivalent, use that.
- Treat formatters and linters required by pre-commit as part of the commit gate.
- Example: in `core-loans`, pre-commit may run lint checks such as `isort`, `black`, and `flake8`; those must pass before committing.
- If pre-commit checks fail because of lint or formatting issues, fix the issues first, rerun the checks, and only then create the commit.
- Only stop and report back when the failure is not something that can be resolved as part of normal commit preparation (for example missing dependencies, broken environment, failing non-lint validation, or unclear/conflicting repo setup).

## Format

```
[<scope>] <type>: <subject>

<body>

<footer>
```

The header is required. Scope and footer is optional. All lines must stay under 100 characters.

## Commit Scope
When commit changes are related to Linear ticket, scope should be included in the commit header. Use linear ticket ID as the scope value, capitalized case.

## Commit Types

| Type | Purpose |
|------|---------|
| `feat` | New feature |
| `fix` | Bug fix |
| `ref` | Refactoring (no behavior change) |
| `chore` | Maintenance tasks |
| `docs` | Documentation only |
| `misc` | General changes that cannot be categorized as other types |

## Subject Line Rules

- Use imperative, present tense: "Add feature" not "Added feature"
- Capitalize the first letter
- No period at the end
- Maximum 70 characters

## Body Guidelines

- Explain **what** and **why**, not how
- Use imperative mood and present tense
- Include motivation for the change
- Contrast with previous behavior when relevant
- Use real newlines in commit bodies; never include literal `\n` sequences

## Commit Command Hygiene

When creating commits from the CLI, do not embed escaped newlines like `\n` inside `-m` strings. That produces literal backslash characters in the final commit message.

Prefer one of these patterns:

```bash
git commit -m "type(scope): Subject" \
  -m "First paragraph with real line wrapping.

Second paragraph.

Co-Authored-By: (the agent's name and attribution byline)"
```

```bash
git commit
```

Use the editor flow when the message needs careful formatting.

## AI-Generated Changes

When changes were primarily generated by a coding agent, include the Co-Authored-By attribution in the commit footer. Agents should use their own identity:

```
Co-Authored-By: (the agent's name and attribution byline)
```

Example: `Co-Authored-By: Ringo <ringo@erudifi.com>`

This is the only indicator of AI involvement that should appear in commits. Do not add phrases like "Generated by AI", "Written with OpenCode", or similar markers in the subject, body, or anywhere else in the commit message.

## Examples

### Feature addition

```
[OI-123] feat: Add create virtual account endpoints

Add CRUD API endpoints for Virtual Account model 

Co-Authored-By: Ringo (ringo@erudifi.com)
```

### Simple fix

```
[LEND-5523] fix: loan contract does not include borrower name

When a loan application is approved, loan contract should be generated that includes borrower name information

Co-Authored-By: Ringo (ringo@erudifi.com)
```

### Dependencies version bumping

```
chore: Bump Django version to 4.2.29 

Bump Django version to from 4.2.27 to 4.2.29

Co-Authored-By: Ringo (ringo@erudifi.com)
```

## Revert Format

```
revert: [OI-123] feat: Add create virtual account endpoints

This reverts commit abc123def456.

Reason: Caused performance regression in production.

Co-Authored-By: Ringo (ringo@erudifi.com)
```

## Principles

- Each commit should be a single, stable change
- Commits should be independently reviewable
- The repository should be in a working state after each commit
